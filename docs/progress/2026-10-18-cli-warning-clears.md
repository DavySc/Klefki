# The live-status warning clears once Claude Code is found (2026-10-18)
Found by the "Review core for correctness" session while reading the engine, and confirmed in the app code. When Claude Code could not be found, the engine sent `CliProblem` and the app showed "Live status is unavailable" in the warnings bar. Nothing ever cleared it. After the user installs Claude Code and presses F5, the engine finds the program, sends `CliVersion` and runs checks again, but the warning stayed.
- `shell.rs`: `Event::CliVersion` also clears `cli_problem`. The engine sends `CliVersion` (the version, or `None` when it cannot tell) only after `locate` found the program (`engine.rs` `refresh`), so a `CliVersion` means the problem is over.
- Test: `the_live_status_warning_goes_once_claude_code_is_found`, seen failing first against main. It covers both `CliVersion(Some(_))` and `CliVersion(None)`.
- Real app (release build, Xvfb): started with no `claude` on `PATH`, the warning shows and every row says "Not checked". With `claude` then linked into a folder on that `PATH` and F5 pressed, the warning is gone, the top bar names Claude CLI 2.1.303, and the rows are checked.
