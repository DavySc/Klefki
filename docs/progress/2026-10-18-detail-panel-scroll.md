# Detail panel scrolls (2026-10-18)
Found in the whole-app UI review of main (`e169d1b`). The detail panel had no scroll area, so whatever was taller than the window was drawn below it and could not be reached. At the size the app opens at (1200x720) this hid the Diagnose result and its Copy report button (Diagnose looked like it did nothing), and the edit form's "Review and save…" for a server with a few arguments. The app tests run at 1100x900, which is why none saw it.
- `shell.rs` `show()`: the detail panel's content is in a vertical `ScrollArea`, keyed by the selected row and tab, so another server's details start at the top. Its right margin is moved inside the scroll area, where egui's floating scroll bar shows, so the bar never covers a button at the panel's edge (it took clicks on the right of an argument's Remove button). `DetailTab` derives `Hash` for the key.
- Tests (each seen failing first against main): `a_long_diagnosis_scrolls_into_view_at_the_opening_size`, `a_long_definition_form_scrolls_to_its_save_button_at_the_opening_size`, `another_servers_details_start_at_the_top` (failed with one shared scroll position), `the_detail_panels_scroll_bar_leaves_the_buttons_beside_it_clickable` (failed before the margin moved). The helper turns the mouse wheel over the panel and first asserts the target starts outside the window, so a test cannot pass vacuously.
- Real app (release build, Xvfb 1200x720, a server that fails with ENOENT): Diagnose, then the wheel over the panel brings "What probably went wrong", the client log and Copy report into view; the General tab form scrolls to "Review and save…"; the panel keeps its width.
- Not done: the panel's heading and tabs scroll away with the content. Keeping them fixed means moving the whole tab body into its own function, a large diff in a file PR #26 is changing; left until after #26.
