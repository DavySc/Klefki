# Performance items that waited on the safe-edits change (2026-10-19)
The performance review of 2026-10-19 left items in `engine.rs`, `docstore.rs` and `shell.rs` until the safe-edits change had landed. Each was checked on main `3549d87` first: all were still there. Numbers are medians (minimum) of interleaved runs of main and this branch, release builds on a shared Linux VM, from scratch benchmarks that are not committed. Expect about ±10% noise.

- **Checks asked for run in the order asked** (`engine.rs`, `Queue::push_now`). Each ask was put in front of the earlier ones, so `klefki-cli status` checked its servers in reverse and its progress line named the server that would be checked last. A new ask now goes behind the earlier asks and ahead of everything else. Tests seen failing first: `checks_asked_for_one_after_another_run_in_the_order_asked` (ran k2, k1, k0, s) and its variant `a_server_asked_for_again_while_waiting_moves_to_the_end_of_the_asks`.
- **Engine reload and queue** (`engine.rs`). A reload compared each row with every row of the last snapshot; queueing compared each job with the whole queue; each local row's project folder was looked up on disk. Now two sets and one lookup per folder per pass (`Folders`). With 4,100 rows (300 projects), the work after reading the files: refresh 35-37 ms (33.3) to 18-19 ms (17.5); reload after a change 17.2-17.5 ms (14.6) to 3.7-3.9 ms (1.5).
- **Switching a user server on or off** (`docstore.rs`, `edit_valid_claude_json`, run under Claude Code's lock). The ops per project, the project-key match and the duplicate-key check were quadratic. Now a map from project to its ops and two sets: 500 projects 5.7-6.1 to 0.8 ms; 2,000: 48-74 to 4 ms; 4,000: 222-242 to 9 ms.
- **Review dialog** (`shell.rs`, `plan_dialog`). Every diff line was laid out on every frame, and the plan was copied on every frame. The plan is now shared (`Arc`), and `DiffTops` keeps where each line goes (per plan, file and width), so only the lines in view are laid out; lines still wrap. Frame time of the dialog alone: 2,000 lines 1.5 to 0.03 ms; 16,000 lines 22 to 0.03 ms. `ScrollArea::show_rows` was not used: it needs rows of one height, and wrapped lines are not. Test seen failing first: `a_long_diff_lays_out_only_the_lines_in_view_and_scrolls_to_its_end`.
- **Add dialog name check** (`shell.rs`, `Places::taken`, runs every frame for every pasted name). It went through all rows once per ticked place for each name. `Taken` now goes through the rows once per frame for all names, and project spellings compare through `api::project_key`, which copies only a path that needs respelling. 100 pasted names, 3,950 rows: new names, user + 1 place 0.50 to 0.11 ms, user + 300 places 56 to 0.39 ms; names that exist in all 300 projects, user + 1 place 0.85 to 0.19 ms, user + 300 places 302 to 1.1 ms. Test: `a_name_is_taken_in_the_ticked_places_that_have_it_however_the_project_is_spelled` (passes on main too: the answer is unchanged), and `a_project_key_is_the_normalised_path_and_borrows_when_it_is_already_that`.
- **Arrow keys in the list** (`shell.rs`, `move_selection`) lower-cased and sorted every row again; they now use the cached grid rows: 0.58 to 0.01 ms at 3,900 rows.
- Already done elsewhere, so skipped: `shadowed` via `contains` (inventory, #21).
- Not done here (out of scope or need a decision): binary size, the four performance decisions in the review (background checks at once, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, remembering checks across restarts, Windows measurements), moving `apply` off the engine thread, `claude --version` cached only after a success, and `klefki-cli status` reading `.claude.json` twice.
