# Release 0.2.0: version (2026-10-20)

Goal: the owner said the next release follows profiles (roadmap item 4), now on main (#57, #58, #59). Step 1 of
`docs/RELEASING.md`, "Cutting a release": set the version and merge it through a pull request.

## Done
- `version = "0.2.0"` in the root `Cargo.toml`; `cargo check` updated `Cargo.lock`. 0.2.0, not 0.1.1: profiles and
  the CLI's `use` are new features.
- The engine's update tests used the workspace version as "this copy" and a signed test release of 0.2.0 as the newer
  one, so the bump made them report "up to date". `EngineConfig::version` now carries this copy's version (the real
  engine: `Version::current()`); the engine tests fix it at 0.1.0, as `update.rs`'s own tests already do. Their
  assertions are unchanged. Re-signing the test release as a higher version was not an option: its secret key is not
  kept.
