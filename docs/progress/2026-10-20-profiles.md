# Profiles, slice 1 (2026-10-20)

Goal: roadmap item 4 (the owner's "profiles", first called server sets): keep named sets of servers and use one in a
project. Decision 012. PR #57.

## Done
- Core: `profiles.rs` keeps profiles in `profiles.json` beside the backups folder: read size-limited and sanitised,
  never written unless read in full (version, limits, unknown fields, bad ids or names all count). Commands
  `Profiles`, `SaveProfile`, `DeleteProfile`; events `Profiles`, `ProfileRefused`.
- Core: `Change::UseProfile` resolves to `disabledMcpServers` switches in one project or every known project, with
  `only` turning every other server there off. The review names members that will still not load there and why
  (another server of the name, policy, plugin off, duplicate, connectors off), members gone, members of another
  project, unapproved project servers, what else goes off, and projects opened later. Projects that share a folder
  name are told apart by the folder above.
- Core: a rename or move applied through Klefki updates the profiles holding the server; its review says so.
- App: Profiles page (nav after Connections): cards with the name as heading, a short server summary (repeated names
  say where; gone ones counted apart), Edit and Delete (asks first), "Use in" listing projects by folder name with
  the folder above muted, sorted, Every project last, a type-to-find box above 10 projects, "Only these servers
  there", and "Use profile…", which opens the usual review. New/Edit form: name with Save and Cancel beside it,
  Enter saves, Escape cancels, what is missing said next to the name; servers grouped as on Connections, with a word
  on what keeps one from loading. A draft survives a visit to another page. Tick boxes are square everywhere
  (`theme::checkbox`).
- Docs: decision 012, CLAUDE.md records the owner-approved `profiles.json` exception, PLAN.md item 4 renamed.
