# App icon (2026-10-19)

Goal: give Klefki its own icon. The owner picked "Server hub" out of three original concepts: a mauve hub with a keyhole, wired to three running servers (pink, green, blue) and one switched off (grey outline), on the Mocha tile.

## Done
- `crates/app/assets/icon/`: `klefki.svg` (32 px and up), `klefki-small.svg` (bolder shapes for 16 and 24 px), `klefki-128.png` (window icon), `klefki-256.png` (README), `klefki.ico` (16 to 256 px), `klefki.icns` (16 to 1024 px), and a README naming each file.
- `scripts/export-icon.py` regenerates every export from the SVGs (needs cairosvg and Pillow); re-running it gives byte-identical files.
- `crates/app/src/main.rs`: the window and taskbar icon is the 128 px PNG baked in with `include_bytes!` and decoded by `eframe::icon_data::from_png_bytes` (eframe already links the PNG decoder; no new dependency). If decoding ever failed the app starts without an icon instead of refusing to start.
- README: the icon above the title.

## Checks
- New tests `the_window_has_the_app_icon` and `the_icon_is_a_tile_with_clear_corners` failed first (no `viewport()`), pass now.
- Full verify: `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check` exit 0, 799 tests passed (deny prints only the existing duplicate-crate warnings).
- `cargo run -p klefki -- --demo` under Xvfb (temp HOME and CLAUDE_CONFIG_DIR): the Klefki window carries `_NET_WM_ICON` 128 x 128, read back with python-xlib.
- Cost: decoding the icon and building the viewport takes 0.05 ms per call (release, mean of 100); the binary grows by the 6.4 KB PNG.
- Not verified: how Windows and macOS show it (no machine here).

## Left
- The `.ico` is not embedded as a Windows executable resource and there is no macOS bundle, so Explorer and the macOS Dock still show the default icon for the file itself. Embedding the `.ico` needs a build script and a resource crate; that is a separate decision.
- Linux desktops on Wayland take the icon from a `.desktop` file, not from the window; packaging is not part of this slice.
