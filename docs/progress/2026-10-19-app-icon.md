# App icon (2026-10-19)

Goal: give Klefki its own icon. The owner picked "Server hub" out of three original concepts: a mauve hub with a keyhole, wired to three running servers (pink, green, blue) and one switched off (grey outline), on the Mocha tile.

## Done
- `crates/app/assets/icon/`: `klefki.svg` (30 px and up), `klefki-small.svg` (bolder shapes for 16 to 24 px), `klefki-256.png` (window, taskbar and Dock icon, and the README), `klefki.ico` (16, 20, 24, 30, 32, 36, 40, 48, 64, 128, 256 px), `klefki.icns` (16 to 1024 px, @1x and @2x, written by hand because Pillow leaves out 16 and 32 @1x), and a README naming each file.
- `scripts/export-icon.py` regenerates every export from the SVGs (needs cairosvg and Pillow); re-running it gives byte-identical files.
- `crates/app/src/main.rs`: the window, taskbar and Dock icon is the 256 px PNG baked in with `include_bytes!` and decoded by `eframe::icon_data::from_png_bytes` (eframe already links the PNG decoder; no new dependency). If decoding ever failed the app starts without an icon instead of refusing to start.
- README: the icon above the title.

## Checks
- New tests `the_window_has_the_app_icon` and `the_icon_is_a_tile_with_clear_corners` failed first (no `viewport()`), pass now.
- Full verify: `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check` exit 0, 799 tests passed (deny prints only the existing duplicate-crate warnings).
- `cargo run -p klefki -- --demo` under Xvfb (temp HOME and CLAUDE_CONFIG_DIR): the Klefki window carried `_NET_WM_ICON` 128 x 128 (before the switch to 256 px), read back with python-xlib.
- Cost: decoding the icon and building the viewport takes 0.29 ms per call with the 256 px PNG (0.05 ms with the 128 px one; release, mean of 100); the binary grows by the 13 KB PNG.
- After the review round and merging main (#2, #4, #5): full verify exit 0, 811 tests passed.
- Not verified: how Windows and macOS show it (no machine here).

## Review (by the "Fix Windows path test" session)
- No blockers. Folded in: the missing `.ico` sizes (20, 30, 36, 40) and `.icns` @1x entries, and the 256 px window icon (eframe on macOS sets it as the Dock icon at run time, so 128 px was blurry on Retina).
- Known limit: eframe takes one window image, so the bold 16/24 px art never reaches the running window's title bar; Windows scales the 256 px art down (Lanczos, in eframe). Getting it there needs a Windows exe resource or an eframe change.

## Left
- The `.ico` is not embedded as a Windows executable resource and there is no macOS bundle, so Explorer still shows a default icon for `klefki.exe` itself (the running window and the macOS Dock do show it: eframe sets both at run time). Embedding the `.ico` needs a build script and a resource crate; that is a separate decision.
- Linux desktops on Wayland take the icon from a `.desktop` file, not from the window; packaging is not part of this slice.
