# Paste: clearer messages for commands it could not read (2026-10-19)
Goal: two open paste items. (1) `false || claude mcp add …`, `echo x | claude mcp add …`, a raw-Markdown inline-code command and `npx @anthropic-ai/claude-code mcp add …` got vague errors ("does not start with claude mcp add", or "Nothing here adds a server"). (2) The owed skipped-lines change from the performance review: name only skipped lines that are likely meant commands, and count the rest in one note. Also taken, same file: a paste of thousands of commands was read in full before being refused for being over 100.

- `paste.rs`, lexer: a claude command after `||`, a pipe or a single `&` is read so it is refused with the reason ("This command uses the shell (||) …"), as a pipe after the command already was. A line that starts with a pipe (a Markdown table row) is not a pipe. A claude command in Markdown inline code, on its own line, after a list marker, or inside a sentence ("Run `claude mcp add …` in a terminal"), is read up to the closing backtick; the sentence around it is not counted as other text. `npx`, `bunx`, `pnpx`, `pnpm dlx` and `yarn dlx` running `@anthropic-ai/claude-code` (with `-y`/`--yes` and an optional `@version`) are read as `claude`.
- `from_commands`: a skipped line is named only when it starts with claude or has `claude mcp` in it (`sudo claude mcp add …`); up to 5, then "Skipped N more lines that are not claude mcp add commands." Every other line is counted in one note: "Skipped a line of other text." / "Skipped N lines of other text." (each line counts, also repeats). Reading stops once there are more than 100 servers; the error now says "That holds more than 100 servers; …".
- Tests (new, each seen failing first): `a_claude_command_after_a_pipe_or_an_or_says_it_uses_the_shell` (variant: a table row), `a_command_in_markdown_inline_code_is_read` (variants: shell inside the code; other code is other text), `claude_code_run_through_a_package_runner_is_read_as_claude` (variants: another package, `npxx`), `other_text_is_counted_in_one_note_and_claude_lines_are_named`, `a_paste_of_many_commands_is_refused_without_reading_them_all`.
- **Tests changed, for review** (the planned behaviour change, nothing else in them): `many_skipped_lines_are_counted_not_all_listed`, `one_more_is_named_not_counted` and the repeat variant now use `claude mcp …` lines for the named list, and the first also checks prose is one count; `a_mistyped_command_is_named_however_much_text_comes_before_it` expects the mistyped line plus one count; `a_command_that_needs_a_shell_…`, `several_commands_…`, `prose_with_an_apostrophe_…` and `a_readme_pasted_…` expect the count note instead of named prose lines; `a_skipped_line_shows_no_secret` checks the prose line is not shown and adds a named claude line that must be masked.
