# Import (M3), 2026-10-19
Goal: PLAN.md's Import. Read a file the user picks as untrusted text, preview what it holds (where it goes, servers already there, the full command or address, a client secret for each OAuth server), and add it as one plan through the existing review. It reads what Export writes. The legacy v1 import is a separate item and is not in this slice.

## Done
- Core `import_file.rs`: reads the picked file through `fsx` (new `read_limited_bytes`, which `read_limited_bom` now uses): at most 256 KiB (the paste limit), never a link, a folder or `.credentials.json` (any case, trailing dots). UTF-8 with or without a byte-order mark, and UTF-16 with one (what Windows PowerShell's `>` writes). Each refusal is a sentence naming the file (sanitised).
- Engine: `Command::ChooseImportFile { shown }` (the system's open dialog, opened by the UI's thread over the window, as Export's save dialog is) and `Command::ReadImportFile(path)` (typed, or dropped on the window). Both answer `Event::ImportFile(ImportFile::{Read, Failed, Cancelled, NoDialog})`; the dialog's answer is waited for, and the file read, on a thread of its own. `Core::choose_import_file`, and `Core::detached_with_pick_dialog` for tests. A dialog that closes within 150 ms was never shown: a path is asked for instead.
- `paste.rs`: `PastedServer::needs`, the `${NAME}` references without a default in the definition's values, each once (a set, so the largest paste stays fast).
- App: an Import button after Add (`TRAY_ARROW_DOWN`, "Import from a file (Ctrl+O)"), Ctrl+O, a palette entry, and a file dropped on the window. The Import dialog is the Add dialog in a third mode (`AddMode::Import`), so places, review, Back, failure and Esc-asks-first work as in Add. It shows the file's name and "Choose another file…"; each server with a tick, its name (editable), what it runs or connects to (wrapped, not cut), which variables must be set where Claude Code runs, hints, and for an OAuth server a hidden client secret field with Show. A server already in a ticked place: "alpha already exists for the user." with Keep the one there (default), Replace it, Import as alpha_2; with two or more, one choice for all. Kept, it is still added where it is not. Replace sends `Change::Replace` for each place it is in (an OAuth one keeps the client secret Klefki has for it, and the dialog says so). A command that asks for a client secret is not imported until one is typed. The line above the buttons says what Review does ("Adds docs and notion for the user. Replaces alpha for the user. Keeps the beta that is there."), or that nothing would change. Once applied, what was imported (and replaced) is selected and the message says "Imported …".
- Found in the real app and fixed: a plan with two diffs of one file (a server written by Klefki plus one added by Claude Code's command) gave both diff boxes one scroll position (egui flagged the ID clash). Boxes are now keyed by their place in the plan. Reproducer `two_diffs_of_one_file_scroll_on_their_own`, seen failing first.
- With the extra button, "N selected" in the toolbar was split over two lines at 1200x720. It is now drawn only when it fits beside the buttons (the detail panel says it too).
- PLAN.md's Import line and the README describe it.
