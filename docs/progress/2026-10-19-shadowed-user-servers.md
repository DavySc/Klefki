# A user server hidden in a project is marked shadowed (2026-10-19)
Goal: a user server whose name is also used by a local server, or by an approved `.mcp.json` server, in a project was never marked; only project servers hidden by a local one were. Claude Code loads local, then approved project, then user, so in that project the user server is not the one that runs.
- `api.rs`: new `ServerRow::shadowed_in`, the projects (as shown) where a user server is hidden. Like the toggle (`enabled`/`disabled_in`), `shadowed` on a user row is `true` only when it is hidden in every known project. Other rows keep their meaning and an empty list.
- `inventory.rs`: user rows are indexed by name as the file spells it; each project collects the user rows its local servers and its approved `.mcp.json` servers hide, and names itself on them (also when its `.mcp.json` is skipped for an unsafe path). Pending and rejected project servers hide nothing: Claude Code does not load them. The project row's own check is now `seen_local.contains(&name)` (perf findings "simpler code"), same meaning, no scan or key lookups.
- App: badge "shadowed in N/M" (as "off in N/M"), with hover text; the "shadowed" badge also gets hover text. The General tab's Shadowed line names the projects, at most 5 then "and N more".
- CLI: notes "shadowed in N of M projects", "shadowed in every project", "shadowed by a local server" (was "shadowed by a closer scope"); JSON adds `shadowed_in` on user rows (new field, schema unchanged).
- Fixture: the user `gateway` lists `C:/Repos/Gateway`, where a local `gateway` exists.
