# Legacy `mcpServersDisabled`: shown read-only, with a migrate action (2026-10-18)
The last M1 item. Started on main after #14 (nifty-brown) landed, as asked, to avoid a third conflict in `ops.rs`.

- **What the key is:** Claude Code 2.1.302 contains no `mcpServersDisabled` at all (checked with `grep -a` on the binary; only `disabledMcpServers` and `disabledMcpjsonServers`). So the servers on an old list are not switched off by it. Assumed shape, not recorded anywhere before: a list of names in a project entry of `~/.claude.json`, like `disabledMcpServers`. A top-level list is not read.
- **Inventory:** `Snapshot::legacy_disabled: Vec<LegacyDisabled>` (project key as in `Snapshot::projects`, the cleaned path, the names once each in file order, `turns_off` = the names not in `disabledMcpServers`, `malformed` when the list holds anything but names). Spellings of one project are merged. The old list never changes a row's on/off state.
- **docstore:** `Op::MigrateLegacyDisabled { project }`, for every spelling of the project, in the same pass as the other list ops: the names not yet in `disabledMcpServers` are appended in order and the old key is removed (`remove_members`). With no `disabledMcpServers`, the old key is renamed in place (key and value replaced, the colon and spacing between them kept), so an entry holding only the old list is never rewritten whole. Refused when the old list is not a list of strings (removing it would lose that), or is there twice. Idempotent for verify. Plan lines: the old list's names as `- `, the added names as `+ `.
- **ops/engine:** `Change::MigrateLegacyDisabled { project }`, verb "Migrate". Summary "Turn off gw and loc in a, as the old switch-off list says", or "Remove the old switch-off list in b" when everything on it is already off; past six names, "and N more". Refused for a project without the list (refresh) and for a malformed one. Note: older versions kept the list and current ones ignore it.
- **Fix found on the way:** warnings and notes are now said once each in a plan, not only when adjacent (`Resolved` used `dedup`). The migration's note came twice with two projects; a variant with two deletes around a user-server toggle repeated "Deleting removes…" before.
- **App:** a notice above the toolbar, "Old switch-off lists in N projects", one line per project ("webapp: github, db, old-thing (github, db are on)", "already off", or "holds something other than server names; edit it in .claude.json by hand"), up to four, with a "Migrate…" button that asks for one plan for every list that can move. Palette: "Migrate old switch-off lists". The button is disabled with a reason when only malformed lists remain, a review is open, or there is no engine.
